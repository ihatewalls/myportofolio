1. When a user wants to access the new section of the website, they will need to click either Experience or Skill in the nav bar. Both of these texts contain an href with calls either show_experience or show_skills, which are the names of paths that are defined inside of the application's urls.py which are accessed by the project's urls.py. These paths contain within them a route in the website, for example /experience for the experience, and also call upon a function that is defined within views.py. The said function accesses variables and models stored within the server and renders them into the template used for the requested webpage. The template has parts depicted by {{}} which are used to load in dynamic variables. When the page loads these sections will be filled by the rendered variables and models. 
2. The reason new data is stored ina  model is so that if we want to add more data, which is something that happens very often, we just need to create a new object instead of creating another hard coded section into the html. This allows for simpler additions and maintenance due to less space being taken by hardcoded elements.
3. makemigrations is a command that we use to plan our future changes to the database. It looks at our models.py and prepares the changes to be applied. migrate is the command that we use to confirm the changes that we intend to make using the plans that were made by makemigrations. In this project, I created a new model, Skill, which was completely new to the database. Because of this, I needed to use makemigrations to plan the addition and migrate so that the model was actually added.
